# Install Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Install Epic games from the Library: manifest → parallel verified chunk downloads → files on disk, with pause/resume/cancel, a queue, an installed list and uninstall.

**Architecture:**
- All Epic and disk logic lives in a new `fishy-core::install` module: manifest parsing, chunks, plan, engine, storage and uninstall. It is tested with hand-built manifests and a wiremock CDN.
- The Tauri app adds a `Downloads` manager: one job at a time, a queue, and a cancellation token per job. It pushes a `downloads-changed` event to Svelte.
- Svelte adds an install store, an Install box, a Downloads page, and badges/tabs/menu in the Library.

**Tech Stack:** Rust (tokio, reqwest, flate2, sha1, fs4, tokio-util), Tauri 2.12 + `tauri-plugin-dialog` (Rust side only), Svelte 5 + Vitest.

**Spec:** `docs/superpowers/specs/2026-11-20-fishy-client-design.md` §6c (also §3.2, §6b, §7, §12).

## Global Constraints
- Manifest info: `https://launcher-public-service-prod06.ol.epicgames.com/launcher/api/public/assets/v2/platform/Windows/namespace/{ns}/catalogItem/{id}/app/{app}/label/Live`, bearer token + `UELauncher/...` UA (existing `http_client()`).
- Manifest and chunk downloads send **no Authorization header**. Chunk UA: `EpicGamesLauncher/11.0.1-14907503+++Portal+Release-Live Windows/10.0.19041.1.256.64bit`.
- Chunk request: timeout 10 s, 7 tries, waits 1, 2, 4… s. 16 chunks in flight.
- Data root `%APPDATA%\FishyClient\`: `installed.json`, `manifests\<app>.manifest`, `downloads\<app>\{manifest,resume.txt,job.json}`. Never tokens.
- Default install folder: `%USERPROFILE%\Games\<FolderName or sanitized title>`.
- Encrypted manifest (stored_as & 2) or feature level ≥ 22 → `InstallError::Unsupported`.
- User copy (exact):
  - "Download stopped: the connection to the download server dropped."
  - "Not enough space on {drive}. Needs {X}, {Y} free."
  - "This game uses a download format Fishy Client can't install yet."
  - "Couldn't write to {folder}. Pick a different folder."
  - "A downloaded file was damaged. Press Retry to download it again."
  - "Couldn't delete some files. Close the game and try again."
  - "Nothing downloading. Pick a game in your Library and press Install."
- Tokens are never logged. No telemetry. `npm.cmd` from `app/`. Rust at `$HOME/.cargo/bin`.
- Tauri: commands that open windows/dialogs must be async. Never name a Svelte prop `state`.

## Review Focus
1. **App closed mid-file:** on resume, that file must be rewritten from zero, never appended. Test: `resume_rewrites_unfinished_file` (Task 8).
2. **A chunk shared by two files far apart:** it must be downloaded once and written into both. Test: `shared_chunk_downloaded_once` (Task 8).
3. **The user deletes the game folder while paused:** resume must notice files listed in resume.txt are gone and download them again. Test: `resume_skips_only_existing_files` (Task 7).
4. **Uninstalling from a folder that has the user's own files:** those stay, and the root isn't removed. Test: `uninstall_keeps_user_files` (Task 9).
5. **The CDN returns garbage or an HTML error page with 200:** treated as a bad chunk and retried, never written. Test: `bad_chunk_is_retried_then_errors` (Task 5).

### Task 8: Download engine

**Files:** Create `install/engine.rs`, `install/speed.rs`

**Interfaces:**
```rust
pub struct Progress { pub downloaded: u64, pub total: u64 }  // compressed bytes. total = job.download_size (whole game);
// downloaded starts at job.download_size - plan.download_size (an estimate for what earlier runs fetched), so a resumed bar doesn't restart at 0 %
pub async fn run_download(client: &InstallClient, store: &InstallStore, job: &JobInfo, manifest: &Manifest,
                          stop: CancellationToken, on_progress: impl Fn(Progress) + Send + Sync) -> Result<(), InstallError>;
pub struct SpeedMeter { /* samples (Instant, bytes), window 3 s */ }
impl SpeedMeter { pub fn new() -> Self; pub fn add(&mut self, now: Instant, total_bytes: u64); pub fn bytes_per_sec(&self) -> f64 }
```
- **Algorithm:**
  1. `finished = store.finished_files(job)`, then `plan = build_plan`.
  2. Stream `plan.chunk_order` through `buffered(16)`, which keeps order. Each item is `client.download_chunk(base_urls[0], m.chunk_dir(), info)` (the stream is raced against `stop.cancelled()`).
  3. For each planned file:
     - Create parent dirs.
     - `File::create` (truncates; this is what makes resume safe).
     - For each part: get the chunk from `cache: HashMap<Guid, Arc<Vec<u8>>>`, pulling from the stream until it arrives.
     - Write `data[offset..offset+size]`, update the Sha1 hasher, decrement uses, and evict at 0.
  4. After a file:
     - flush and close
     - compare SHA-1 → `DamagedFile(filename)`
     - `store.mark_finished`
  5. Report progress (Progress callback) after each chunk arrives.
  6. On `stop` → `Err(Stopped)`. On write errors → `Io { folder: install_path display, detail }`.
- `finish_install` is **not** called here; the manager calls it, so tests can check both separately.
- File writes use `std::fs` inside `tokio::task::spawn_blocking` per file (or `tokio::fs`). Either is fine; keep it simple.
