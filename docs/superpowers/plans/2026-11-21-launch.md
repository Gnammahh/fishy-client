# Launch Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Play button on installed games that starts the game signed in as the user, the way Legendary does on Windows.

**Architecture:**
- A new `fishy-core::launch` module holds the Epic calls (exchange code, ownership token), a pure argument builder and process start.
- The library `Game` keeps the catalog launch attributes.
- The Tauri app adds one command, `play_game`. The Library card gets Play, Starting… and an error box.

**Tech Stack:** Rust (reqwest, wiremock, tempfile), Tauri 2, Svelte 5, vitest.

**Spec:** `docs/superpowers/specs/2026-11-20-fishy-client-design.md` §6d

## Global Constraints
- Argument order and flag spellings exactly as in §6d "Command line".
- The exchange code and ownership token never go into logs, errors or `Debug` output (`[redacted]`).
- User-facing copy exactly as in the §6d error table.
- The program path goes through `install::store::file_path` (no escaping the install folder).
- Old `library.json` caches and UI `Game` objects without the new field must still deserialize (`#[serde(default)]`).

## Review Focus
- **A launch option with quotes and spaces** (`-a "-b c"`): it becomes `-a` and `-b c`. Tested in Task 2.
- **An executable saved with a leading `/` or with `/` separators:** it resolves inside the install folder. Tested in Task 2.
- **Offline but the game isn't allowed offline:** no Play offline button. Tested in Tasks 4 and 5.
- **Epic returns an error body for the ownership token:** this is a Rejected error, not a corrupted `.ovt` file. Tested in Task 3.
- **A session that expired while the app was open:** the UI goes back to login instead of showing an error. Tested in Task 5.

### Task 2: Argument builder (`launch/command.rs`) and errors (`launch/error.rs`)
**Produces:**
- `split_args(&str) -> Vec<String>`
- `LaunchCommand { program: PathBuf, working_dir: PathBuf, args: Vec<String> }`, whose `Debug` redacts `-AUTH_PASSWORD=` values.
- `LaunchInputs<'a> { installed: &InstalledGame, game: &Game, display_name: &str, account_id: &str, locale: &str, exchange_code: Option<&Secret>, ovt_path: Option<&Path> }`
- `build_command(&LaunchInputs) -> Result<LaunchCommand, LaunchError>`:
  - third-party store → `ThirdParty(store)`
  - unsafe path or missing file → `MissingProgram`
- `language_from(Option<&str>) -> String`
- `LaunchError { Network, SignedOut, Rejected(String), MissingProgram, NeedsAdmin, Spawn(String), ThirdParty(String), NotInLibrary, NotInstalled }` with `user_message(title)`, using the §6d copy.

**Tests:**
- full argument order with code and ovt
- offline form (`-AUTH_PASSWORD=`)
- split with quotes
- leading-slash executable
- `..` executable refused
- missing file
- third-party store
- debug output redacted
- `language_from("en-US")` gives `en`, `None` gives `en`
- each message

### Task 3: Epic calls (`launch/client.rs`)
**Produces:**
- `LaunchClient::new()` and `with_base_urls(account, ecommerce)`
- `exchange_code(&Secret) -> Result<Secret, AuthError>`: `GET /account/api/oauth/exchange` and read `code`.
- `ownership_token(&Secret, account_id, ns, catalog_id) -> Result<Vec<u8>, AuthError>`: POST form `nsCatalogItemId`, raw bytes. A non-2xx answer or an `errorCode` JSON body is `Rejected`.

**Tests (wiremock):** success with the bearer header checked, rejection and network failure for each call.

### Task 4: Orchestration (`launch/mod.rs`)
**Produces:**
- `prepare_launch(client, session: Option<&Session>, identity: (&str, &str), installed, game, locale, ovt_dir) -> Result<LaunchCommand, LaunchError>`
  - `session` None means offline.
  - It fetches the code, plus the ownership token when `requires_ot` is set, writes `{ns}{catalog}.ovt` and builds the command.
- `start(&LaunchCommand) -> Result<(), LaunchError>`: OS error 740 → `NeedsAdmin`.
- `clean_ovt_dir(&Path)`

**Tests:**
- online with OT (the file is written and the flag added)
- offline skips Epic
- Network error mapped
- clean removes only `.ovt` files

### Task 5: App command and UI
- **Auth:**
  - `AuthManager::session()` is refactored out of `access_token` and returns a fresh `Session`.
  - `AuthManager::saved_identity() -> Option<(String, String)>`
- **Tauri:**
  - `play_game(app_name, offline) -> Result<(), PlayError { message, can_offline, signed_out }>`
  - `.ovt` cleanup at setup
  - `sys-locale` for the language
- **UI:**
  - `play(app, offline)` in `installs.ts`
  - Play button, Starting… for 5 s, error box with Try again / Play offline. `signed_out` calls `auth.retry()`.
  - devMock `play_game`.
- **vitest:**
  - Play only on installed cards
  - Starting… then back to Play
  - error message shown
  - Play offline only when `can_offline`
  - `signed_out` calls `retry_auth`
