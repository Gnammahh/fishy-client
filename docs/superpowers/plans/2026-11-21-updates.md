# Updates Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Show when an installed game has a newer version and patch it, downloading only the new pieces and copying the rest from the old files (spec goal 5). Also add an auto-update setting and a warning before playing an outdated game.

**Architecture:**
- The install engine learns to update. The plan gets an optional old manifest: unchanged files are skipped, parts of changed files are copied from disk, changed files are swapped in through a temporary file, and removed files are deleted at the end.
- The Library refresh also returns Epic's newest version per game.
- The app adds `update_start`, settings commands, update-aware Downloads, and Library and Settings UI.

**Tech Stack:** Rust (wiremock, tempfile), Tauri 2, Svelte 5, vitest.

**Spec:** `docs/superpowers/specs/2026-11-20-fishy-client-design.md` §6e (and §6c for the install engine it extends)

## Global Constraints
- UI copy exactly as in §6e:
  - "Update available"
  - "Updating…"
  - "*Title* has an update waiting. You'll play the older version, and some online games won't start until they're updated."
  - "Play anyway" / "Update now" / "Cancel" / "Don't show this again"
  - "Updates can be paused but not cancelled."
  - "Couldn't get the update from Epic. Try again later."
- Temporary name: `<name>.fishy-update` in the same folder.
- `settings.json` defaults: `auto_update: false`, `warn_outdated_play: true`. A damaged file means the defaults.
- Every new serialized field is `#[serde(default)]`, so old `job.json`, `library.json` and UI objects still load.
- Writing still goes through `store::file_path`, so nothing is written outside the install folder.

## Review Focus
- **A changed file whose old copy the user edited or deleted:** the reuse check fails, the file is rebuilt from downloads once and the update finishes. Tested in Task 3.
- **Pausing after the last file but before removed files are deleted:** Resume deletes them and finishes. Tested in Task 3.
- **Restarting the app during a paused update:** it comes back as a paused **update** (no Cancel), with the old manifest loaded. Tested in Task 5.
- **The new manifest has the same version as installed** (the asset list ran ahead): no job, nothing breaks. Tested in Task 5.
- **Auto-update on:** a refresh never queues a game that already has a job. Tested in Task 7.

### Task 1: Compare manifests and the update plan
**Files:**

**Produces:**

### Task 2: `JobInfo.update_from`, `finish_install` keeps the date, uninstall covers both manifests

### Task 3: The engine runs updates
**Files:** `engine.rs`
- `run_download` and `run_download_with` take `old: Option<&Manifest>`. They use `build_update_plan` and the plan's `space_needed`.
- **Reused parts:** read from the old file (opened once per file) at the given position.
- **Replace files:** written to `<target>.fishy-update` and renamed over the target after the SHA-1 check.
- **Damaged reuse:** a SHA-1 mismatch on a file that used reuse rebuilds it once from chunks fetched one by one with `client.download_chunk`.
- **Removed files:** deleted after the loop with `delete_named_files(.., remove_root=false)`.

**Tests (wiremock fixture extended with an old manifest written to disk first):**
- `update_skips_unchanged_files_and_never_downloads_reused_chunks`: the reused chunk's mock expects 0 calls, unchanged files keep their modified time, and new contents are correct.
- `update_deletes_removed_files_and_leaves_no_temp_files`
- `update_rebuilds_a_file_whose_old_copy_was_edited`
- `update_paused_then_resumed_finishes`
- `resume_after_all_files_still_deletes_removed_files`

### Task 5: App backend
**Files:** `app/src-tauri/src/lib.rs`, `downloads.rs`
- `Job.old: Option<Arc<Manifest>>`. On startup, a job with `update_from` loads `store.installed_manifest`.
- `DownloadItem.update: bool`.
- `cancel` of an update returns `Err("Updates can be paused but not cancelled.")`.
- `update_start(app_name)`:
  - fetch manifest info and the manifest
  - if it's the same version as installed, return the view unchanged
  - otherwise plan with the old manifest, check space, save the job with `update_from`, and enqueue
  - errors: "Couldn't get the update from Epic. Try again later." for network or manifest failures, and session failures map as for installs
- `settings_get`, `settings_set(settings)`.
- `uninstall_game` drops a paused update job from the manager first.
- `library_refresh` saves `latest_versions`.

**Tests (unit, in `downloads.rs`):**
- `view_marks_update_jobs`
- `cancelling_an_update_is_refused`
- `restored_update_job_keeps_its_old_manifest`
